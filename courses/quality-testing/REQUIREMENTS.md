# Якість та тестування програмних систем: перевірені вимоги

Спільна частина: створити New Paste на Pastebin, довільний текст і назва, термін 10 хвилин, перевірити результат. Друга частина — індивідуальний варіант за номером у журналі. Наприклад, варіанти 1/11/21: Tricentis Demo Web Shop, пошук music, advanced search із виробником і ціною 0–10, вибір першого результату, додавання до кошика й перевірки. Персональний варіант у цьому аудиті не підтверджено. У прочитаній Лаб1.docx детальне оформлення звіту не задане. Для №2 і №3 картка дозволяє обрати варіант самостійно; обидві .doc тепер прочитані.

Джерело: вебперегляд Teams, 2026-10-09. Ці вимоги стосуються лише прямо зазначених номерів робіт. Не переносити їх автоматично на інші лабораторні.

Позитивні й негативні сценарії. На вибір: Demo Web Shop (реєстрація, вхід, кошик, вихід); Petstore (реєстрація, вхід, додавання/вилучення з кошика, вихід); OrangeHRM (вхід, особиста сторінка, оформлення/скасування відпустки, вихід). Звіт обов’язковий, числових параметрів оформлення не задано.

## №3: JMeter

Загальна частина: сценарій 2–3 кроки для сайту з назвою на першу літеру прізвища (саме прізвище не записувати в Git); Results Tree і Graph results у Thread Group; 5, 10, 20 користувачів, Ramp-up Period 10; скриншот графіка та аналіз. Друга частина на вибір: Petstore (реєстрація/вхід/кошик/вихід); OpenMRS demo (вхід, реєстрація й видалення тестового пацієнта); Gatling computer database (додавання/редагування/видалення тестового комп’ютера). Застосувати генератори випадкового рядка/дати/числа JMeter і перевірку успішності кожного тесту. Звіт: титул, умова, опис розв’язку, тестування, висновки. Номер №2/3 обирає користувач.
